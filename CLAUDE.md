# AI Personal Command Center

Personal dashboard that syncs Gmail, Google Calendar and SUCourse (Moodle iCal) into Postgres, uses Claude to extract deadlines and tasks from emails, and has a chat agent that answers questions like "What do I need to finish before Friday?"

## Stack
- Backend: FastAPI, Python 3.12, managed with uv (run everything with `uv run ...` from `backend/`)
- Database: PostgreSQL 17 + pgvector (Homebrew), database `command_center`, migrations with Alembic
- LLM: Anthropic API via the `anthropic` SDK; models set in `backend/.env` (EXTRACT_MODEL, AGENT_MODEL)
- Embeddings: nomic-embed-text via Ollama (768 dims)
- Frontend: React + Vite + TypeScript, Tailwind, TanStack Query (in `frontend/`)
- Machine: M1 MacBook Air, 8 GB RAM

Before any text goes to Claude (extraction, cleanup, evals), `app/llm/redact.py` masks Pakistani CNICs, card numbers (Luhn-checked), IBANs (mod-97-checked) and phone numbers as [REDACTED-<LABEL>]; all patterns are in its REDACTIONS list, and `uv run python -m app.llm.redact` counts matches in stored emails. - Done (Milestone 5): Google Calendar sync in `app/sync/calendar.py` (primary calendar, next 60 days, singleEvents, all-day events at Europe/Istanbul midnight, events that vanish from the window are deleted, past ones kept) and SUCourse sync in `app/sync/sucourse.py` (Moodle .ics export URL saved in sync_state via POST /sync/sucourse/url and never echoed or logged; each VEVENT becomes an assignment item plus a task with created_by="sucourse", priority high if due within 3 days). POST /sync/calendar, /sync/sucourse, /sync/all. No LLM calls. Tests in `tests/test_sync.py`
- Done (Milestone 6): chat agent in `app/llm/agent.py`, endpoints in `app/llm/agent_routes.py`. POST /chat runs a manual tool-use loop (max 5 model calls) with AGENT_MODEL. Read tools list_tasks, list_events, search_items run SQL and never return email bodies, sensitive or noise emails. create_task is saved to pending_actions and only runs on POST /actions/{id}/confirm (or /cancel). Each call is logged to llm_usage as purpose="agent". Tests in `tests/test_agent.py` use a fake Anthropic client
- Done (polish before evaluation): POST /sync/all now also runs extraction on up to EXTRACT_ON_SYNC_LIMIT (default 50) unprocessed emails and returns its counts and estimated cost; the shared run lives in `app/sync/runner.py`. A process-wide lock means only one sync or extraction runs at a time (a second one gets 409). `app/scheduler.py` runs the same thing every 30 minutes with APScheduler inside the API process (max_instances=1, first run 30 min after startup so `--reload` restarts don't trigger it), for every user with a stored Google token; users needing reconnect are skipped, and each run logs counts and cost (no titles). Switch it off with BACKGROUND_SYNC_ENABLED=false. Only run one uvicorn worker, or each worker would schedule its own job. SUCourse titles containing a word from EXAM_KEYWORDS in `app/sync/sucourse.py` (Mid, Midterm, Final, Exam, Quiz) are high priority, "... opens" events stay low, and every SUCourse sync re-scores all open SUCourse tasks except ones whose priority you changed (PATCH /tasks/{id} sets tasks.priority_set_by_user). Tests in `tests/test_background.py` and `tests/test_sync.py`
- Cost estimates come from the price table in `app/llm/pricing.py` (keyed by model name, dated ids map to their alias). A model missing from the table gives estimated_cost_usd = null, so add a row when changing EXTRACT_MODEL or AGENT_MODEL Prices include cache writes (1.25x input) and cache reads (per-model read price); llm_usage logs cache_creation_input_tokens and cache_read_input_tokens next to input/output tokens, and calls return a `Usage` tuple
- Prompt caching: extraction marks the tool + system prompt and the "Today + open tasks" block with cache_control, so later emails in a run re-read them from the cache; the agent caches its static system prompt (the current time is a separate block after it) and uses top-level automatic caching across tool rounds. Haiku 4.5 only caches prefixes of 4096+ tokens: extraction's prefix is ~3.7K plus the open tasks, so it caches only with roughly 14+ open tasks, and the agent (~1.5K) rarely does. Below the minimum the markers cost nothing
- Out of API credit: `app/llm/client.py` turns billing errors (402, billing_error, or the 400 "credit balance is too low") into CreditTooLow. Like a bad API key, it stops extraction immediately without marking emails processed or failed; /sync/all returns extraction.credit_low, other endpoints return 402 {credit_low: true}, and the frontend shows a banner
- Done (Milestone 7): dashboard endpoints in `app/dashboard/` (GET /today returns open tasks grouped into overdue / today / this_week plus today's events and the next 5 SUCourse items, already sorted; GET /tasks?status=open|done|expired; PATCH /tasks/{id} for status and priority). After Google login the backend redirects to FRONTEND_URL. The agent's list_tasks also returns open undated tasks when a date filter is used, and the prompt asks Claude to mention them in one line. Tests in `tests/test_dashboard.py`
- Done (Milestone 8): extraction eval in `backend/evals/` (see its README). `uv run python -m evals.export` writes ~60 varied processed emails (no sensitive/noise) to `evals/emails.jsonl`, which is gitignored and must never be committed. You label them at #/label, backed by dev-only `/evals/...` endpoints in `app/dev/routes.py` (localhost only, off with DEV_ENDPOINTS_ENABLED=false) that never return the model's prediction. `uv run python -m evals.run` extracts each labeled email with its sent time as today and no open tasks, scores actionable accuracy, task recall/precision (word-overlap title matching, no LLM judge) and due dates (same day, time within 1 h), and writes a Markdown report to `evals/results/` (subjects only, no bodies). Bump `PROMPT_VERSION` in `extract.py` when changing the prompt. A held-out test set (`--set test` on export and run, #/label?set=test, `evals/test_emails.jsonl`, gitignored) has 25 emails that are never in the tuning set; label it once and run it only on final prompt versions, never tune on it. Report titles and filenames include the set name. The test set is picked with tags from the email itself only (no "had tasks" tag from model output). Tests in `tests/test_evals.py`
- One-time Gmail backfill: `uv run python -m app.sync.backfill [--max-cost 0.60]` imports emails 30 to 60 days old (`BACKFILL_QUERY` in `app/sync/gmail.py`, same promotions/social filter, sync_state untouched), then extracts unprocessed emails with `process_unprocessed(..., max_cost_usd=...)`, which stops before a call that would likely pass the cap (spent + average per call). It prints counts and cost only. The sync lock in `app/sync/runner.py` is also a Postgres advisory lock, so a script like this and the API's background job never run at the same time (tests swap it out in `tests/conftest.py`)
- Done (Milestone 9): several Google accounts per user. `google_accounts` (user_id, email unique, encrypted refresh token, scopes) replaced oauth_tokens; `items.account_id` and `sync_state.account_id` say which account a row came from (NULL for SUCourse), and both unique keys include account_id with NULLS NOT DISTINCT. Logic in `app/auth/accounts.py`: signing in with any linked account opens its owner; GET /auth/google/link (signed in) adds another account to the current user (409 if another user has it); GET /accounts lists them; `uv run python -m app.auth.accounts merge <from> <into>` merges an empty user's accounts into another user. Gmail and Calendar sync loop over every account (`run_full_sync` skips accounts needing reconnect and lists them in reconnect_needed; it raises only if all do). A new account's first Gmail sync looks back 14 days (`FIRST_RUN_DAYS`) and its first extraction runs newest first with a $0.30 cap (`FIRST_SYNC_COST_CAP_USD` in `app/sync/runner.py`); emails past the cap are marked "Skipped: first-sync cost cap". University accounts (`UNIVERSITY_DOMAINS`) send every email to extraction except sensitive/noise ones, emails matching `COURSE_ADMIN_PATTERNS` (subject/body: NS101, recitation, worksheet, learning assistant, capital LA) or `COURSE_ADMIN_SENDERS` ("Skipped: course admin"), and senders in the `university_blocked_senders` table (user_id, lowercased address; "Skipped: blocked sender"). Both checks live in `university_skip()` in `app/llm/extract.py`; the agent's search_items hides the same emails, including ones read before the block, and university accounts are left out of eval exports. The personal account doesn't use them. Settings > University senders (`app/auth/university.py`: GET /university/senders, POST /university/senders/block and /unblock) lists senders by address, display name, email count and latest date, never subjects or bodies, and never goes to Claude; blocking also marks that sender's open tasks from the university account as done. `uv run python -m app.sync.dryrun --email <account> [--days 14]` prints only counts (per-filter skips including blocked senders, emails to Claude, cost estimate) and writes nothing. Tasks and events carry `account` ("Personal" / "Sabancı") for the tag in the frontend; #/settings lists accounts with "Link another Google account". Tests in `tests/test_accounts.py` (the migration/linking/merge ones create a throwaway Postgres database)
